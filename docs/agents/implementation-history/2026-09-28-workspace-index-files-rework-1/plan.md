## Summary

Close the four actionable follow-up items left open by the Workspace Index Files project: repair a stale GUI test fixture that has been failing on a clean `main` checkout and polluting every GUI test run; add an audit-log trail to the destructive **global** repository-deletion cascade; harden that cascade's clone-folder deletion guard from a lexical containment check to the realpath-based symlink-escape chain already established elsewhere in the codebase; and convert four manually-verified QA edge cases into permanent regression tests. Along the way, the path-guard helpers currently private to `src/orchestration/workspace-index.ts` are extracted into a shared `src/utils/path-guard.ts` module so both consumers run the same verified implementation, and the choke-point guard test's stale allowlist entry is removed and its existence-only assertion strengthened so the same staleness cannot recur silently. The separately implemented project-level unlink route remains out of scope.

## Architectural Context

The relevant slice of the layered architecture (`AGENTS.md` §5: Storage → Models → Error Log → Git → Orchestration → Server → CLI, with `src/utils/` beneath all of them):

- **`src/orchestration/workspace-index.ts`** renders and writes the three generated index files. Lines 265–395 hold a self-contained, module-private path-guard chain: `isLexicallyContained()`, `findDeepestExistingAncestor()`, `resolveSymlinkTarget()`, `bestEffortRealpath()`, `resolveRootRealPath()`, `escapesRootViaRealpath()`, `isDirectoryShaped()`, and the `MAX_SYMLINK_RESOLUTION_DEPTH = 40` cap. `writeWorkspaceIndexFiles()` (L421) runs lexical → realpath → shape in that order before any I/O, reporting rejections through its `skipped` array rather than throwing.
- **`src/orchestration/repository-orchestrator.ts`** owns clone lifecycle across workspaces. `removeRepositoryFromProject()` (L203–L237) deletes clone folders behind a **lexical-only** `path.resolve()` + `startsWith()` guard before `fs.rmSync(..., { recursive: true })`. `deleteRepositoryGlobally()` (L249–L266) cascades that method across every referencing project, then removes the global store entry. The class already accepts `errorLogManager?: ErrorLogManager` (L33–L40) and uses it at three sites inside `addRepositoryToProject()` (L130, L155, L172); `src/server/index.ts` (L112–L118) supplies it in production.
- **`src/server/routes/projects.ts`** owns the separately reachable `DELETE /api/projects/:id/repositories/:repoId` unlink flow. It directly calls `projectManager.removeRepository()` and then `workspaceArtifacts.regenerateProject()`; it does not invoke `RepositoryOrchestrator.removeRepositoryFromProject()`. This plan does not change, delegate, or audit that route.
- **`src/error-log/error-log.types.ts`** defines `ErrorSeverity = 'error' | 'warning' | 'audit' | 'info'` (L6) and an `ErrorLogContext` limited to `ProjectId` / `WorkspaceId` / `RepositoryId` (L12–L21); free-form structured detail belongs in `Details?: string` (L48).
- **`gui/public/js/api.js`** `credentialOptions(id)` (L175–L201) transforms the server's `{ credentials, autoSelected }` body into the flat `{ credentialId, label, host, auto }[]` shape the GUI selectors consume. `src/server/routes/repositories.ts`'s `buildCredentialOptionsResponse()` (L157–L180) is the single producer of that body for both credential-options routes.
- **`src/tests/workspace-artifacts-chokepoint.test.ts`** statically scans production sources for direct imports of the four raw generator/remover functions, permitting only the choke-point module and a `TEMPORARY_EXCEPTIONS` allowlist.

## Approach / Architecture

Six independent, small changes plus a documentation pass, sequenced so the one shared refactor lands before its new consumer.

1. **Fixture repair, not production change.** The failing `credentialOptions` test feeds a client-shaped array where the client expects a server-shaped object. Production is self-consistent (verified against `buildCredentialOptionsResponse()`); only the fixture moves.
2. **Guard extraction before guard reuse.** The path-guard chain moves verbatim into a new `src/utils/path-guard.ts`, exported, with `workspace-index.ts` re-pointed at it and its behaviour unchanged. This mirrors the precedent recorded as repository insight `cdcc6460` ("build shared UI primitives before their second consumer"): extract first, then consume. Extraction also creates the test seam the guards have never had — today they can only be asserted indirectly through `writeWorkspaceIndexFiles()`'s `skipped` array.
3. **Guard hardening at the delete site.** `removeRepositoryFromProject()` gains the realpath symlink-escape check alongside a retained **strict-descendant** lexical check, using the extracted module. The equality-permitting `isLexicallyContained()` contract remains correct for writer file paths, but recursive deletion must additionally reject `resolvedClonePath === resolvedProjectsFolder` so malformed persisted IDs can never authorize removal of the projects root. Its existing throw-on-violation contract is preserved — this is a delete path with no `skipped` channel, and a thrown error is what the route already handles.
4. **Audit trail at the completed global-deletion cascade, not at its route.** The per-project unlink entry is emitted inside `removeRepositoryFromProject()` only after both `projectManager.removeRepository()` and `workspaceArtifacts.regenerateProject()` succeed; the cascade-summary entry is emitted inside `deleteRepositoryGlobally()` after `repositoryManager.remove()` succeeds. The live `DELETE /api/repositories/:id` route reaches this orchestrator cascade, so its per-project entries carry a populated `Context.ProjectId` that the error-log GUI already filters on. The separate `DELETE /api/projects/:id/repositories/:repoId` route does not reach this code and remains unaudited by this plan. This defines the audit success boundary: a guard, project mutation, or artefact-regeneration throw emits no per-project entry for that project; a global-store-removal throw emits no global summary entry, while entries for already completed per-project cascade removals remain.
5. **Allowlist correction plus assertion strengthening.** The stale entry is removed (verified: `src/server/routes/workspaces.ts` imports none of the guarded identifiers) *and* the guard test is tightened to assert that any future entry still imports a guarded identifier — fixing the instance and the class of failure together.
6. **Coverage conversion.** Four QA-verified-but-untested behaviours become permanent assertions, with the `makeProject()` route-test factory generalised to express multi-workspace projects since that limitation is what forced the weaker assertion in the first place.

## Rationale

- **Fix the test, not the client.** Three independent agents across four work packages confirmed the failure is unrelated to the plan's changes; this research confirmed *why*. Changing `api.js` to also accept a pre-flattened array would make the client tolerant of a shape no server route ever emits — tolerance that would then need its own maintenance and would mask a genuine wire-shape regression.
- **Extract rather than duplicate.** `bestEffortRealpath()` is the fix for a HIGH-severity finding, tested through two rework cycles and manually stress-tested against symlink cycles and broken intermediate hops. A second hand-written copy in `repository-orchestrator.ts` would be a second thing to get right, and the two would drift. The extracted module has two named consumers today, so it is not speculative structure.
- **Audit the global delete path because it is the most destructive one in the system.** `deleteRepositoryGlobally()` recursively removes clone folders across every referencing project and then drops the global store entry, yet a credential label edit is audited and this is not. The asymmetry is what the Security Auditor flagged (OWASP A09). The project-level unlink route is a separate mutation path with distinct best-effort artefact-error handling, so bringing it under the orchestrator or independently auditing it would expand this plan beyond the flagged global cascade.
- **Strengthen the guard test rather than delete the allowlist.** The allowlist is the documented mechanism for an intentionally-incomplete migration, and the synthesis named it a reusable pattern. Its failure mode was a weak assertion, not the mechanism; removing the mechanism would discard the pattern while leaving future migrations with nowhere to record a known exception.
- **Generalise the fixture factory rather than hand-roll one project.** `makeProject()` is used across the whole `projects.test.ts` suite; an optional workspace parameter serves every future multi-workspace route test, where an inline one-off would serve exactly one. To be explicit about the strength of that claim: of the 22 `makeProject()` call sites in the file today, the DELETE artefact-set test at L473–L483 is the **only** current beneficiary — every other call site is legitimately single-workspace and stays on the default. This is therefore a forward-looking generalisation, not a response to existing demand, and it is justified on cost proportionality rather than urgency: one optional parameter with a backward-compatible default is cheaper to add now than to retrofit once a second multi-workspace test has already hand-rolled its own literal.

## Pattern Alignment

- **Single-concern utility module** — follows `src/utils/slug.ts` and `src/utils/version.ts`: a small module with a file-level doc block and named exports. `src/utils/path-guard.ts` adopts the same shape.
- **Layering direction** — follows `AGENTS.md` §5. `src/utils/` sits beneath orchestration; both `workspace-index.ts` and `repository-orchestrator.ts` importing from it preserves the existing direction (`repository-orchestrator.ts` already imports from `../git/` and `../config/`).
- **Node16 ESM import extensions** — follows `AGENTS.md` §4 (MUST): every new relative import carries `.js`.
- **Orchestrator self-logging** — follows `src/orchestration/repository-orchestrator.ts` L130/L155/L172, where the orchestrator emits its own error-log entries via the optional `errorLogManager?.append(...)`.
- **Audit-entry shape** — follows `src/server/routes/repositories.ts` L523–L534: `Severity: 'audit'`, a subsystem-specific `Source`, a verb-shaped `Operation`, a populated `Context`, and a human-readable `Message`.
- **Deliberate departure — a new `Source` value.** Existing audit entries all use `Source: 'credential-audit'`. Repository lifecycle deletion is a different subsystem, so this plan introduces `Source: 'repository-audit'`. Reusing `'credential-audit'` for a clone-folder deletion would corrupt the error-log source filter the GUI exposes; the departure is the narrower change.
- **Multi-workspace test fixtures** — follows `src/tests/repository-orchestrator.test.ts` L255–L272: seed with `workspaceManager.create()` *then* `workspaceOrchestrator.createWorkspace()`. WP-009 established that skipping the first call is a test defect, not leniency to preserve.
- **Temp-file cleanup** — follows `constraints.md` "Test Conventions" and `AGENTS.md` §4 (MUST): any new temp-dir test registers a `process.on('exit')` handler.

## Detailed Steps

1. **Repair the stale `credentialOptions` test fixture.**
   In `gui/public/js/api.config.test.mjs` (L389–L401), replace the response body with the real wire shape the server emits — `{ credentials: [{ id: 'cred-1', label: 'My Token', host: 'github.com', token: '***' }], autoSelected: 'cred-1' }` — while keeping the assertion on the flat transformed result `[{ credentialId: 'cred-1', label: 'My Token', host: 'github.com', auto: true }]`. Add a second matching credential with no `autoSelected` match so the fixture's input and output are observably different shapes (insight `e134b941`), proving the transform ran rather than that the body passed through. Make no change to `gui/public/js/api.js`. Verify the whole GUI suite is green afterwards, since this failure has been reported as noise across five work packages.

2. **Extract the path-guard chain into `src/utils/path-guard.ts` (new file).**
   Move, verbatim in behaviour, from `src/orchestration/workspace-index.ts` (L265–L395): `MAX_SYMLINK_RESOLUTION_DEPTH`, `isLexicallyContained()`, `findDeepestExistingAncestor()`, `resolveSymlinkTarget()`, `bestEffortRealpath()`, `resolveRootRealPath()`, `escapesRootViaRealpath()`, `isDirectoryShaped()`. Export `isLexicallyContained`, `bestEffortRealpath`, `resolveRootRealPath`, `escapesRootViaRealpath`, `isDirectoryShaped`, and `MAX_SYMLINK_RESOLUTION_DEPTH`; keep `findDeepestExistingAncestor()` and `resolveSymlinkTarget()` module-private unless a test requires otherwise. Carry the existing explanatory doc comments across unchanged — particularly `bestEffortRealpath()`'s account of the broken-symlink `existsSync` gap and `escapesRootViaRealpath()`'s conservative-on-error behaviour. Add a file-level doc block naming both consumers. Update `workspace-index.ts` to import from `../utils/path-guard.js` and delete the moved definitions; no other line of `workspace-index.ts` changes.

3. **Harden `removeRepositoryFromProject()` with the realpath symlink-escape check.**
   In `src/orchestration/repository-orchestrator.ts` (L203–L237), resolve the root once via `resolveRootRealPath(this.config.projectsFolder)` alongside the existing `path.resolve()` root, and for each computed clone path retain the current strict-descendant lexical guard before running `escapesRootViaRealpath(clonePath, resolvedRootRealPath)` and then `fs.rmSync()`. Do not substitute `isLexicallyContained()` directly for this guard: its equality-permitting semantics are needed by writer file paths, but the delete path must either keep `resolvedClonePath.startsWith(resolvedProjectsFolder + path.sep)` or explicitly require both `isLexicallyContained(resolvedClonePath, resolvedProjectsFolder)` and `resolvedClonePath !== resolvedProjectsFolder`. Throw on either violation, preserving the current plain-`Error` contract and message style so `DELETE /api/repositories/:id`'s route-level classification (`src/server/routes/repositories.ts` L397–L420) is unaffected. Keep the two root values distinct — the lexical check compares against `path.resolve()` and the realpath check against the realpath'd root — per the synthesis's "two distinct root values" finding, which exists because unifying them falsely rejects legitimate paths on hosts where the root itself sits behind a symlink (macOS `/tmp` → `/private/tmp`). Note in a comment that the directory-shape check is deliberately not applied here: the target of a delete is expected to be a directory. Add a regression test with malformed persisted project/workspace/repository IDs that resolve the clone path to `projectsFolder`, asserting the method throws and `fs.rmSync()` is never reached.

4. **Add the audit-log trail to the global repository-deletion cascade.**
   In `src/orchestration/repository-orchestrator.ts`, emit `this.errorLogManager?.append({ Severity: 'audit', Source: 'repository-audit', Operation: 'unlink-repository', Context: { ProjectId, RepositoryId }, Message: … })` naming the repository and project and stating that clone folders were deleted from all workspaces **only after** `projectManager.removeRepository()` and the subsequent `workspaceArtifacts.regenerateProject()` both succeed. `deleteRepositoryGlobally()` invokes this method for each affected project; no change is made to the independently implemented `DELETE /api/projects/:id/repositories/:repoId` route. In `deleteRepositoryGlobally()`, collect the affected project IDs during the cascade loop and, after `repositoryManager.remove()` succeeds, emit a summary entry `{ Severity: 'audit', Source: 'repository-audit', Operation: 'delete-repository-global', Context: { RepositoryId }, Message: …, Details: JSON.stringify({ AffectedProjectIds: [...] }) }` — `Details` is used because `ErrorLogContext` (`src/error-log/error-log.types.ts` L12–L21) has no field for a project list. Every call must use the optional-chaining form, since `errorLogManager` is optional on the constructor. This ordering is the explicit success boundary: a guard, project mutation, or artefact-regeneration throw emits no entry for that incomplete per-project cascade removal; a global-store-removal throw emits no `delete-repository-global` summary, but leaves the already-completed per-project `unlink-repository` entries intact.
   **Test mechanism for the new audit assertions (AC-05, AC-06, AC-07):** the shared `makeFixture()` helper (`src/tests/repository-orchestrator.test.ts` L65–L85) constructs `RepositoryOrchestrator` with four arguments and wires no `errorLogManager`, so it cannot observe appended entries. Do **not** extend it. The new audit-entry tests instead construct the orchestrator inline with a real `new ErrorLogManager(config)` as the fifth constructor argument and assert via `errorLogManager.list({ source: 'repository-audit' })`, following the file's own existing precedent at L606–L637, L672–L691, and L719–L738. For the global-store-removal failure case, use a controllable repository-manager test double or a local failure seam whose `remove()` throws after the per-project calls, assert `deleteRepositoryGlobally()` throws, assert no `repository-audit` / `delete-repository-global` entry exists, and assert the completed per-project `unlink-repository` entries remain. The AC-07 test is the one exception: it uses `makeFixture()` unchanged, since a fixture without an `errorLogManager` is exactly the no-injection case it asserts.

5. **Remove the stale choke-point exception and strengthen its guard test.**
   In `src/tests/workspace-artifacts-chokepoint.test.ts`, empty `TEMPORARY_EXCEPTIONS` (verified: `src/server/routes/workspaces.ts` imports none of the four guarded identifiers since WP-012) and rewrite its doc block to describe the allowlist as the mechanism for a future intentionally-incomplete migration, noting it is currently empty by design and stating the two conditions an entry must satisfy. Replace the existence-only assertion (L98–L106) with one asserting, for each entry, that the file exists **and** that it still contains a named import of at least one `GUARDED_IDENTIFIERS` member — reusing the same import-block regex the first test already uses, so the two tests cannot disagree about what "imports a guarded identifier" means. Add a focused unit-style assertion over the shared matcher with synthetic input (a string that imports a guarded identifier, and one that merely mentions it in a comment) so the regex itself is covered rather than only exercised.

## Risks & Mitigations

| Risk | Mitigation |
|------|------------|
| **The guard extraction silently changes behaviour** (e.g. a recursion default or a `catch` swallow lost in the move) | Move the code verbatim with its doc comments; require the existing `workspace-index.test.ts` suite to pass unchanged (AC-03) before any consumer is re-pointed; add direct unit tests for the extracted functions (step 7) so the guards are asserted at both levels. |
| **The realpath guard rejects legitimate deletions** on hosts where `projectsFolder` sits behind a symlink (macOS `/tmp` → `/private/tmp`) | Keep the two root values distinct exactly as `workspace-index.ts` does — lexical check against `path.resolve()`, realpath check against `resolveRootRealPath()`. AC-04 includes a symlinked-root test that fails if the roots are unified. |
| **`escapesRootViaRealpath()`'s conservative-on-error behaviour turns a transient filesystem error into a failed deletion** | The behaviour is deliberate and already shipped on the write path. Because the delete path throws rather than skipping, the failure is loud and the operation is retryable; the error message must name the offending path so the cause is diagnosable. |
| **Audit entries flood the error log** on a cascade across many projects, pushing older entries past `DEFAULT_MAX_ERROR_LOG_ENTRIES` (500) | One entry per affected project plus one summary — bounded by the project count, which is small in this tool's usage model. The summary entry carries the full affected-project list in `Details`, so the cascade remains reconstructible even if individual entries age out. The 500-entry bound is not newly contended: `addRepositoryToProject()` already emits into the same ring buffer from three sites (`Source: 'credentials'` at L132 and L174, `Source: 'clone'` at L157), one set per workspace per call, so the two new audit sources are an incremental consumer of an existing, already-exercised bound rather than a new pressure on it — and their per-deletion volume is lower than the per-add volume already tolerated. |
| **Emptying `TEMPORARY_EXCEPTIONS` leaves an unused mechanism** that later rots | The strengthened assertion iterates the set, so an empty set is a passing no-op rather than dead code with no test; the rewritten doc block states the two conditions a future entry must satisfy, and the assertion enforces the second one mechanically. |
| **`makeProject()`'s new parameter breaks existing call sites** in `projects.test.ts` | The parameter is optional with a `['STABLE']` default reproducing today's literal shape; AC-10 requires existing call sites to remain unchanged and the suite to stay green. |
| **`ctx generate` is unavailable in the execution environment**, blocking the documentation step | The hand-maintained manifest files (`constraints.md`, `api-surface.md`) are the load-bearing documentation and are edited directly. If `ctx` cannot run, record that in the work package rather than hand-editing `.context/**`, which `AGENTS.md` forbids. |
